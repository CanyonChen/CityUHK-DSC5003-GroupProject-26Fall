## 3. 贡献比例填写口径

建议按“实际投入 + 交付责任”而不是只按代码行数计算，至少考虑：

1. 需求、设计、数据库与文档的实际编写量。
2. 代码实现、调试、测试用例与缺陷修复的实际投入。
3. 联调、部署、演示准备和交付整合的实际投入。
4. 是否承担了关键路径、阻塞问题或跨模块协调。

比例以 5% 或 10% 为最小刻度，8 人合计必须为 100%。若某人承担跨组协调或关键修复，应在“具体任务”中写明，不能只写“参与开发”。
