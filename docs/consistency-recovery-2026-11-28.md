# 一致性与恢复改进

修改继续保留在 PR #3，不合并、不部署。摄像头不属于验票方案，验票仍使用文本票码。

| 问题 | 当前处理 |
|---|---|
| 付费确认缺少库存数量校验 | 免费/付费共用 inventory.sellHeldSeats，锁定全部明细座位、核对当前预留订单，条件更新数量必须相等；出票、订单、支付和审计在同一事务 |
| 已售座位释放依赖历史订单 | 以唯一有效票据证明当前售出归属，排除 VOID 历史票；锁定库存和有效票，SQL 限制当前有效票属于该订单且没有其他有效归属，数量不符回滚 |
| 前端超时重试换键 | 幂等键按账号和业务内容存入 sessionStorage；不确定响应后保留，刷新页面仍可重试找回原订单 |
| 财务页面只显示正常退票 | 两端后台统计分别显示正常退票、异常退款、全部成功退款及净票款公式；异常退款确认不再声称释放门票/座位 |
| 对账只重放部分通知 | 已验证结果先独立持久化，模拟适配器可读取；检查未知支付及成功但未履约的付款；未知退款保留待确认并审计 |
| 核销缺少状态条件 | 在原行锁和唯一核销记录之外加 VALID 条件更新与行数校验，明确二维码过期 |
| 隔离级别依赖环境 | 新连接显式使用配置的 REPEATABLE READ，健康检查验证；创建订单单次事务继续 READ COMMITTED |
| 缺少通用巡检 | inventory_consistency_check.cjs 用只读一致性快照检查预留、当前有效票归属、履约、核销、退款上限；报告异常，不修数据 |

没有新增表或修改已有数据库字段。售出归属采用有效票据关联，不把历史 order_items 当作当前归属。库存恢复失败会保留可审计的支付结果供后续核查和重试。

模拟适配器的证据来自已验证通知持久化记录，不代表已经对接真实支付机构。没有可验证结果时保持 UNKNOWN/PENDING，退款需要人工确认。

默认对账周期统一为 60 秒，最小记录年龄 30 秒，每类单批 50；按最近检查时间轮转积压记录。后台展示最近运行时间及未知支付、待确认退款和检查计数。

测试包含：库存被篡改后付费确认回滚且保留支付证据；模拟成功后未履约的恢复及重放；未知付款不误判；退款无法查询时保留状态与审计；旧订单不释放其他有效票对应的座位；二维码过期/重复核销；浏览器中丢失预留响应、刷新并复用同键；财务字段和运行对账按钮。最终结果以 PR 最新 Project checks 为准，属于自动化验收。

全库巡检还发现旧种子数据把已退款、VOID 门票对应的座位保留为 SOLD，以及分批插入导致预留期限相差毫秒；种子生成和导入已修正。AC-07/AC-25 的人工 SOLD 测试标记在断言后改回 BLOCKED，避免把无对应门票的假售出状态留给后续检查。巡检规则没有放宽。
